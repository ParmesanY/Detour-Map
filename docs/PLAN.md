# Detour Map — план

Публичная карта блокировок в России почти в реальном времени: **что** заблокировано, **у какого провайдера** и **в каком регионе**, **как** (DNS-подмена, DPI по SNI, блок IP, «заморозка 16 КБ», замедление, белые списки), с историей. Часть семейства Detour; на карте ссылка «обойти с Detour».

Почему не OONI: медленный, не про Россию, мало зондов у российских провайдеров, нет разбивки «как именно блокируют» в понятном виде.

## Компоненты

```
 зонд (CLI)  ─┐
              ├─ HTTPS POST (JSON, < 16 КБ) ─▶ collector (Cloudflare Worker) ─▶ D1 (SQLite)
 Detour (opt-in)┘                                  │ ASN + регион из request.cf,                │
                                                   │ IP не сохраняется                           ▼
                                                   └────────── агрегаты (cron) ─▶ API ─▶ сайт с картой
```

1. **probe** — библиотека замеров (C#, `Detour.NetProbe`) + маленький CLI поверх неё. Та же библиотека подключается в Detour.
2. **collector** — Cloudflare Worker (TypeScript): принимает отчёт, проверяет, определяет ASN и регион по `request.cf` (Cloudflare даёт это сам, своя GeoIP-база не нужна), пишет в D1, IP выбрасывает.
3. **aggregator** — cron-триггер того же Worker: раз в 10–15 минут сводит сырые замеры в таблицу «цель × ASN × регион × час».
4. **site** — статика (Cloudflare Pages): MapLibre GL + границы регионов РФ (GeoJSON из OSM, ODbL — указать атрибуцию), таблица по провайдерам, график истории.

## Что измеряем (на одну цель)

Всё — напрямую через физическую сетевую карту (мимо VPN-туннеля), как уже делает `NetCheckReport`.

| Шаг | Как | Результат |
|---|---|---|
| DNS | системный резолвер vs DoH 1.1.1.1/8.8.8.8 по IP | `ok` / `stub` (bogon/заглушка) / `nx` / `none` / `timeout` |
| TCP | connect к реальному IP (из DoH), порт 443 | `ok` / `timeout` / `rst` / `refused` |
| TLS (SNI цели) | handshake с настоящим SNI | `ok` / `rst` / `timeout` / `alert` |
| TLS (контрольный SNI) | тот же IP, нейтральный SNI | отличает блок по SNI от блока IP |
| HTTP | GET до 64 КБ | байты, статус, `freeze_at` (≈16 КБ = TSPU на хостингах) |
| QUIC/UDP | Initial на 443/udp | `ok` / `timeout` |
| Скорость (опц.) | время на 1 МБ | для замедлений (YouTube) |

Вердикт (`dns`, `ip`, `sni`, `freeze16k`, `throttle`, `quic`, `ok`, `whitelist`) считает **сервер** по сырым полям, чтобы правила можно было менять без обновления клиентов.

Контроль: `ya.ru` и `speed.cloudflare.com`. Если не работает контроль — замер не учитываем (нет сети / белые списки на мобильном → отдельный вердикт `whitelist` по региону).

**Список целей** — версионированный JSON в репозитории, отдаётся collector'ом (`GET /v1/targets`). Начальный набор = `_sites` из `NetCheckReport` + ключевые хосты пресетов Detour (YouTube, Discord, Telegram, Instagram, X, Rutracker, хостинги…). Сервисы, которые сами отказывают России (OpenAI, Spotify…), не меряем — `RefusesRussia` уже есть.

## Формат отчёта (v1)

Модель — `probe/Detour.NetProbe/Report.cs`, правила вердиктов — `Verdicts.cs`, общие примеры для C# и TS — `spec/verdict-cases.json`.

```json
{
  "v": 1,
  "client": "probe-cli/0.1.0",        // или "detour/7.25.6"
  "targets_ver": 1,
  "net": "home",                      // или "mobile"
  "ts": "2026-11-16T14:00Z",          // округлено до часа
  "env": { "vpn_adapter": false, "dpi_bypass": false, "nic": true },
  "results": [
    { "t": "x", "dns": "ok", "tcp": "ok", "tls": "timeout", "tls_ctrl": "ok" },
    { "t": "vultr", "dns": "stub", "dns_ip": "10.10.34.36", "tcp": "ok", "tls": "ok",
      "http": { "bytes": 16384, "status": 200, "ms": 8013, "complete": false, "error": "timeout" } },
    { "t": "youtube", "dns": "ok", "tcp": "ok", "tls": "ok",
      "http": { "bytes": 65536, "status": 200, "ms": 601, "complete": true }, "quic": "timeout" }
  ]
}
```

Нет ни IP пользователя, ни имени компьютера, ни ID установки (`dns_ip` — адрес заглушки провайдера, не пользователя). Хост цели не передаётся: сервер знает его по `t` и `targets_ver`. Сервер отбрасывает отчёт с `dpi_bypass`, а также с `vpn_adapter` без `nic` (зонд не смог привязаться к физической карте).

DNS провайдера меряется своим UDP-запросом к DNS-серверам физической карты (не системным резолвером: под TUN он отдаёт фейковые адреса). DNS `timeout` и QUIC `error` вердиктом не считаются.

## Приватность (главное требование)

- IP видит только Worker в момент запроса: берём `cf.asn`, `cf.asOrganization`, `cf.regionCode` (и город — только если в нём ≥ N зондов), IP не пишем никуда, включая логи (Workers Logs выключены / без IP).
- Против спама — псевдоним на сутки: `HMAC(IP, соль дня)` в KV с TTL 24 ч, соль меняется ежедневно и нигде не хранится дольше суток. Лимит: N отчётов в час на псевдоним.
- На карту попадает ячейка «цель × ASN × регион», только если в ней ≥ 3 разных псевдонимов за окно — защита и от отравления, и от деанонимизации одиночного зонда в маленьком городе.
- В Detour — строго opt-in, выключено по умолчанию, с понятным текстом «что отправляется» и кнопкой «показать отчёт».
- Автор анонимен, как публичный Detour: аккаунт Cloudflare на отдельную почту, без личных данных в коде и хостинге.

## Данные (D1)

- `reports(id, ts_hour, asn, as_org, region, net, client, targets_ver)`
- `results(report_id, target, dns, tcp, tls, tls_ctrl, http_bytes, freeze_at, quic, kbps, verdict)`
- `agg_hourly(target, asn, region, hour, n_probes, n_ok, verdicts_json)` — то, что читает сайт.
- Сырые `reports/results` хранить 30 дней, агрегаты — бессрочно (история).

D1 free tier: 5 ГБ, 5 млн чтений/сутки, 100 тыс. записей/сутки — с батч-вставкой одного отчёта хватит на тысячи отчётов в день.

## API

- `POST /v1/report` — приём отчёта (202 / 400 / 429).
- `GET /v1/targets` — список целей.
- `GET /v1/map?target=youtube&window=24h` — регион → доля блокировок + основной способ.
- `GET /v1/target/{t}/isps?window=24h` — разбивка по провайдерам.
- `GET /v1/history?target=…&asn=…` — ряд по часам.
- Ответы кэшируются на краю Cloudflare (60–300 с).

## Риски

- **Cloudflare в РФ режут** (заморозка 16 КБ): отчёт маленький, должен проходить; сайт с большими файлами (GeoJSON регионов) может не открыться без обхода — держать GeoJSON упрощённым (< 16 КБ не выйдет, но можно разбить/сжать), у пользователей Detour откроется в любом случае. Запасной домен/зеркало — позже.
- Если collector недоступен напрямую — отправлять через VPN нельзя (ASN будет VPN-сервера). Вариант: не отправлять, повторить позже.
- Отравление данных — порог по псевдонимам + отбрасывание выбросов по ASN.
- Мобильные операторы: ASN общий на всю страну, регион по IP часто неточен — показывать мобильные отдельно и с оговоркой.

## Структура репозитория

```
detour-map/
  probe/      C#: Detour.NetProbe (библиотека) + Detour.NetProbe.Cli (detour-probe, AOT) + тесты (TUnit)
  collector/  TypeScript: Worker, схема D1, миграции, тесты (vitest + miniflare)
  site/       статика: MapLibre, без фреймворка или Preact
  spec/       targets.json (встроен в библиотеку), verdict-cases.json (общие тесты C#/TS)
  docs/       PLAN.md, privacy.md (текст для пользователей)
```

Detour подключает `probe/Detour.NetProbe` (git submodule или скопированный исходник) и даёт галочку «Помогать карте блокировок».

## Этапы

1. **M1 — зонд.** Библиотека + CLI, печатает JSON-отчёт локально. Перенос логики из `NetCheckReport` и `detour-netcheck.cmd`. Тесты на классификацию.
2. **M2 — collector.** Worker + D1 + `POST /v1/report` + агрегатор. Локально через `wrangler dev`.
3. **M3 — сайт.** Карта регионов, выбор цели, таблица провайдеров, история.
4. **M4 — Detour.** Opt-in, отправка раз в N часов и после «Проверить сеть».
   Проверено на M1: под TUN Detour (sing-box strict_route) и при запущенном winws любой UDP с физической карты не проходит — DNS провайдера даёт `timeout`, QUIC `error`. Варианты: разрешить UDP 53/443 с физической карты на время замера, мерить DNS/QUIC только без TUN, или слать эти поля пустыми. winws искажает результаты по сайтам из своего списка: на время замера пропускать их или останавливать zapret.
5. **M5 — запуск.** Деплой, privacy.md, README, ссылка из Detour и обратно.
